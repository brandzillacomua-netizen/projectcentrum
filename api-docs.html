REST API

Backend API Documentation

Повна документація REST API для виробничого бекенду. Всі ендпоінти захищені JWT-токеном (окрім /health та /api/auth/login).

Base URL https://api.your-domain.com
Auth Bearer JWT
Format application/json
Framework Axum (Rust)
📖

Огляд

API побудований на фреймворку Axum (Rust). Всі відповіді повертаються у форматі JSON. Ідентифікатори — UUID v4. Дати — ISO 8601 UTC.

Доступ до ресурсів контролюється через RBAC (Role-Based Access Control). Кожен ендпоінт вимагає конкретний дозвіл у форматі module:action. Дозволи вбудовані у JWT-токен і не потребують додаткових запитів до БД на кожному запиті.

🔑

Аутентифікація

Усі захищені ендпоінти вимагають заголовок Authorization з Bearer-токеном.

HTTP Header 
Authorization: Bearer <jwt_token>

JWT payload містить:

JWT Claims
{
  "sub": "uuid",           // User ID
  "email": "string",
  "full_name": "string",
  "roles": ["shop_chief", "operator"],
  "permissions": ["warehouse:reserve", "orders:read"],
  "iat": 1700000000,
  "exp": 1700086400
}
⚠️

Стандартні помилки

200OK — успішний запит
201Created — ресурс успішно створено
400Bad Request — невірні параметри або бізнес-логіка відхилила запит
401Unauthorized — відсутній або невалідний JWT-токен
403Forbidden — недостатньо прав (відсутній дозвіл)
404Not Found — ресурс не знайдено
409Conflict — дублікат ресурсу (напр. email або код)
500Internal Server Error — внутрішня помилка сервера

Auth

POST /api/auth/login Вхід у систему ▼

Публічний ендпоінт. Повертає JWT-токен та інформацію про користувача.

Request Body
JSON
{
  "email": "admin@example.com",    // required
  "password": "secret"              // required
}
Відповідь 200
JSON
{
  "token": "eyJhbGci...",
  "user": {
    "id": "uuid",
    "email": "admin@example.com",
    "full_name": "John Doe",
    "roles": ["admin"]
  }
}
Відповіді
200Успішна аутентифікація
401Невірний email або пароль
GET /api/auth/me Поточний користувач ▼

Повертає інформацію про поточного авторизованого користувача з токена. Не робить запитів до БД.

Відповідь 200
JSON
{ "id": "uuid", "email": "...", "full_name": "...", "roles": [] }
POST /api/auth/refresh Оновлення токена ▼

Видає новий токен з оновленим терміном дії та актуальними permissions з БД. Body не потрібен — авторизація через поточний токен.

Відповідь 200
JSON
{ "token": "eyJhbGci..." }

Документи регулюють рухи товарів на складі. При підтвердженні PostgreSQL тригер автоматично оновлює залишки.

GET/api/stock/documentsСписок документів▼
Query Params
ПараметрТипОбов'язковістьОпис

limitintoptionalМакс. 200, default: 50
offsetintoptionalDefault: 0
POST/api/stock/documentsСтворити документ (Draft)▼

Документ типу transfer вимагає warehouse_dest_id. Статус після створення: draft.

Request Body — CreateDocumentDto
JSON
{
  "doc_type": "receipt",           // required: receipt | issue | transfer | adjustment | write_off | production_in | production_out | return_to_supplier | return_from_customer | inventory
  "warehouse_id": "uuid",           // required
  "warehouse_dest_id": null,        // required for transfer
  "counterparty_id": null,          // optional
  "production_order_id": null,      // optional
  "purchase_order_id": null,        // optional
  "doc_date": null,                 // optional ISO date
  "notes": "Прихід від постачальника",// optional
  "lines": [{
    "characteristic_id": "uuid",   // required
    "qty": 100,                     // required
    "unit_price": 150.00,           // optional
    "currency": "UAH",             // optional
    "location_id": null,            // optional
    "location_dest_id": null        // optional for transfer
  }]
}

JSON
{ "document": {}, "lines": [] }
PATCH/api/stock/documents/:id/confirmПровести документ▼
